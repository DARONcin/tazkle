# Contribuir

El proyecto está en preproducción. Los cambios deben mantener alineadas documentación, contratos y recursos visuales.

## Flujo

1. Crear una rama corta desde `main`.
2. Describir el problema y el alcance.
3. Actualizar ADR o documentación si cambia una decisión.
4. Incluir pruebas cuando exista implementación.
5. Abrir un pull request pequeño y verificable.

## Convenciones

- `feat:` funcionalidad.
- `fix:` corrección.
- `docs:` documentación.
- `design:` recursos o sistema visual.
- `security:` controles o correcciones de seguridad.
- `chore:` mantenimiento.

## No incluir

- Credenciales o datos reales de clientes.
- Recursos visuales exploratorios sin registrar su estado.
- Cambios directos a versiones aprobadas del producto sin una nueva decisión.
- Dependencias sin justificación y revisión de licencia.
